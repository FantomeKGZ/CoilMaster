# Arduino Uno — очередь ACK/NACK и повторная передача

## Назначение

Arduino Uno не считает событие синхронизированным сразу после отправки. Событие удаляется из очереди только после подтверждения ESP32.

## Очередь

В оперативной памяти хранится до четырех событий:

- `RUN_STARTED`;
- `RUN_COMPLETED`.

События обрабатываются строго по порядку. Новый запуск станка не зависит от доступности ESP32, но результаты остаются в очереди до подтверждения.

## Подтверждения

Arduino принимает:

```text
CMP1|ACK|<run_id>|RECORDED
CMP1|ACK|<run_id>|SAVED
CMP1|ACK|<run_id>|RECEIVED
CMP1|ACK|<run_id>|DUPLICATE
```

`DUPLICATE` считается успешным подтверждением, потому что запись с тем же `run_id` уже существует на ESP32.

## Ошибки

При ответе:

```text
CMP1|NACK|<run_id>|<reason>
```

событие остается в очереди и повторяется через увеличенный интервал.

Если ответа нет, передача повторяется через 1500 мс. После `NACK` повтор выполняется через 3000 мс.

## CRC

Arduino и ESP32 используют одинаковый алгоритм `CRC-16/Modbus`:

- начальное значение `0xFFFF`;
- полином `0xA001`.

Это исправляет прежнее несоответствие, когда Arduino использовала CRC-CCITT, а ESP32 проверяла CRC-Modbus.

## Ограничение текущей версии

Очередь пока хранится только в RAM Arduino Uno. При полном отключении питания неподтвержденные события теряются. Следующий этап надежности — сохранение критического `RUN_COMPLETED` в EEPROM с контролем износа и восстановлением после запуска.
