# Аудит целостности журнала намотки

## Назначение

Добавлен независимый модуль `WindingJournalHealth`, который читает журнал `/data/winding-runs/events.ndjson` и формирует диагностический отчёт без изменения сохранённых данных.

Модуль предназначен для последующего подключения к сервисному API и экрану диагностики ESP32.

## Проверяемые свойства

Аудит проверяет:

- доступность файла журнала;
- `schema_version = 1`;
- наличие корректных `run_id`, `session_id` и `completed_runs`;
- допустимый тип события `RUN_STARTED` или `RUN_COMPLETED`;
- отсутствие двух одновременно активных запусков;
- совпадение `run_id` и `session_id` запуска и завершения;
- последовательное увеличение `completed_runs` внутри одной сессии;
- сброс счётчика завершений при переходе к новой `session_id`.

## Результат

`WindingJournalHealthReport` содержит:

- `recordCount` — число непустых записей;
- `malformedRecordCount` — число записей с неправильной структурой;
- `startedCount` и `completedCount`;
- `activeRunCount`;
- `readable` — удалось ли прочитать журнал;
- `sequenceConsistent` — сохранён ли допустимый порядок событий.

Метод `healthy()` возвращает `true`, только если журнал читается, не содержит malformed-записей, последовательность корректна и одновременно существует не более одного активного запуска.

## Безопасность

Аудит работает только на чтение. Он не исправляет, не удаляет и не переписывает журнал автоматически. Это исключает скрытую потерю истории при обнаружении повреждения.

## Текущий этап

Модель и реализация аудита добавлены в прошивку. Публикация отчёта через HTTP API и отображение в веб-интерфейсе будут выполнены отдельным этапом после подтверждения зелёной сборки.
