# Выбор клиента при создании ремонта

## Цель

При создании ремонта оператор больше не вводит `client_id` вручную. Клиент выбирается из каталога.

## Мобильный и настольный интерфейс

Обновлены:

- `/mobile/repairs.html`
- `/desktop/repairs.html`
- `/mobile/clients.html`
- `/desktop/clients.html`

## Логика выбора

Форма ремонта загружает клиентов через:

`GET /api/clients`

В списке отображаются имя и телефон.

Поддерживается прямой переход:

`/mobile/repairs.html?client_id=12`

`/desktop/repairs.html?client_id=12`

Последний выбранный клиент сохраняется локально под ключом:

`cm-selected-client`

Перед автоматическим выбором интерфейс проверяет, что клиент присутствует в загруженном каталоге.

## Быстрое добавление

На странице ремонтов можно создать клиента через:

`POST /api/clients`

После успешного создания новый клиент автоматически выбирается в форме ремонта.

## Отображение ремонтов

В списке ремонтов вместо одного числового `client_id` отображаются имя и телефон клиента, если карточка найдена в каталоге.

## Совместимость

Backend API ремонта не изменён. При создании по-прежнему передаются:

- `client_id`
- `motor_id`
- `received_at`
- `complaint`
- `comment`
