# CoilMaster OS — AI Context Handoff

Этот каталог предназначен для быстрого продолжения разработки в новом чате, новым ИИ-ассистентом или после длительного перерыва.

## Как начать работу в новом чате

Перед началом разработки нужно прочитать файлы в таком порядке:

1. `PROJECT_STATE.md` — текущее состояние проекта и точка продолжения.
2. `DECISIONS.md` — уже принятые архитектурные решения, которые нельзя менять без отдельного пересмотра.
3. `IMPLEMENTATION_LOG.md` — что уже реализовано и какими коммитами.
4. `IDEAS_BACKLOG.md` — будущие идеи, улучшения и функции.
5. `SESSION_LOG.md` — краткая история последних рабочих сессий.
6. Основные документы проекта:
   - `README.md`
   - `ARCHITECTURE.md`
   - `Docs/Protocol/CMP_Specification.md`
   - `Docs/Protocol/CMP_API.md`
   - `Engineering/Package_001_CMP_Core/Docs/Dependency_Matrix.md`

## Готовый запрос для нового чата

Скопировать в новый чат:

> Открой репозиторий `FantomeKGZ/CoilMaster`. Сначала прочитай `Docs/AI_CONTEXT/README.md` и все файлы, перечисленные в нём. Затем проверь актуальное состояние ветки `main`, последние коммиты и продолжи работу с точки, указанной в `PROJECT_STATE.md`. Не возвращайся к уже завершённым тестам оборудования. После каждой значимой реализации обновляй `PROJECT_STATE.md`, `IMPLEMENTATION_LOG.md`, `SESSION_LOG.md`, а новые идеи записывай в `IDEAS_BACKLOG.md`. Архитектурные решения фиксируй в `DECISIONS.md`.

## Правила ведения контекста

После каждой значимой работы необходимо:

- обновить статус реализованного модуля;
- указать изменённые файлы и коммиты;
- записать результат проверки или компиляции;
- зафиксировать следующую точку продолжения;
- добавить новые идеи в backlog;
- не удалять старые решения, а помечать их как заменённые;
- не считать модуль завершённым без компиляции, теста и обновления документации.

## Источник истины

При расхождении данных приоритет такой:

1. фактический код в актуальной ветке;
2. утверждённая спецификация;
3. `DECISIONS.md`;
4. `PROJECT_STATE.md`;
5. `IMPLEMENTATION_LOG.md`;
6. история чатов.

История чатов не должна быть единственным местом хранения важного решения.
