# Checkpoint 116 — Dedicated Cash Web UI

Date: **2026-08-26**  
Branch: **`cmp-protocol-v1`**

## Status

**SOFTWARE GREEN**.

## Implemented

Dedicated desktop cash UI:

```text
/desktop/cash.html
```

Cash UI is separate from costing. `costing.html` remains cost/price/margin; cash records money only.

The page uses the existing checkpoint 112 APIs:

```text
GET  /api/payments?repair_id=...
POST /api/payments
GET  /api/payments/balance?repair_id=...
GET  /api/repairs?status=ALL&limit=20
GET  /api/repairs/delivery?repair_id=...
```

Supported operator actions:

```text
PAYMENT    -> ADD
CORRECTION -> ADD | SUBTRACT
```

Every write requires explicit operator confirmation and sends `confirmed=true`. Cash history is append-only; there is no PUT/PATCH/DELETE path.

## Money precision

`amount_minor`, charged/paid/debt/credit remain integer minor units. UI conversion and rendering use JavaScript `BigInt`, avoiding lossy `Number` conversion for backend `uint64_t` amounts.

## Navigation

Dedicated cash navigation is exposed from:

```text
/desktop/                 -> Касса
/desktop/client-details.html?client_id=... -> Касса клиента
```

Client-scoped navigation is convenience only; the cash backend remains repair-owned for writes and derives client identity from authoritative repair state.

## Safety

Cash UI never:

- starts a machine or job;
- controls SSR;
- mutates warehouse/Material Request;
- changes repair price;
- blocks or authorizes delivery;
- rewrites/deletes historical cash events.

Delivery remains independent from zero balance; post-CLOSED/post-DELIVERED payment remains supported.

## Permanent regression

```text
Tests/Web/check_cash_ui.js
```

It verifies bounded reads, append-only PAYMENT/CORRECTION writes, explicit confirmation, exact repair identity, authoritative currency, correction provenance, BigInt minor-unit rendering, dedicated navigation, separation from costing, and absence of machine/warehouse/destructive shortcuts.
