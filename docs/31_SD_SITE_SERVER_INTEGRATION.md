# Интеграция WEB-портала с microSD

## Выполнено

`CM_StaticSiteServer` подключён к основной прошивке ESP32.

После запуска ESP32 обслуживает WEB-файлы из каталога:

```text
/web/
```

Ожидаемая структура карты памяти:

```text
/web/
├── index.html
├── mobile/
│   └── index.html
├── desktop/
│   └── index.html
└── sites/
    └── reference/
        ├── mobile/
        │   └── index.html
        └── desktop/
            └── index.html
```

## Рабочие маршруты

```text
/                         экран выбора версии
/mobile/                  мобильная версия CoilMaster
/desktop/                 версия CoilMaster для ПК
/sites/reference/         выбор версии справочника по настройке браузера
/sites/reference/mobile/  мобильный справочник
/sites/reference/desktop/ справочник для ПК
```

API остаётся отдельным от статических файлов:

```text
GET  /api/status
POST /api/jobs
```

Маршруты `/api/*` никогда не интерпретируются как пути на microSD.

## Поведение при отсутствии WEB-файлов

Если карта памяти доступна, но каталог `/web` отсутствует, ESP32 показывает встроенную служебную страницу с инструкцией скопировать WEB-файлы на карту.

В ответе `/api/status` добавлено поле:

```json
{"web_storage_ready":true}
```

Оно позволяет мобильной и ПК-версии отдельно контролировать доступность WEB-каталога.

## Подготовка microSD

Содержимое репозитория:

```text
firmware/esp32/web/
```

нужно скопировать на карту памяти как:

```text
/web/
```

После перезапуска ESP32 интерфейс станет доступен по адресу точки доступа, обычно:

```text
http://192.168.4.1/
```

## Безопасность

Сервер отклоняет пути с `..` и обратными слешами. Неизвестные API возвращают JSON 404, а неизвестные страницы — текстовый 404.
