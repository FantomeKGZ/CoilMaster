# CoilMaster — склад провода и расчет стоимости

## 1. Основной принцип учета

Провод учитывается по массе, а не по длине.

Основная внутренняя единица хранения — грамм. Пользовательский интерфейс может отображать граммы или килограммы.

Примеры:

```text
Остаток: 12 450 г
Остаток: 12,45 кг
```

## 2. Карточка складской позиции

Для каждой позиции провода хранятся:

- уникальный ID;
- марка провода;
- материал: медь или алюминий;
- диаметр;
- производитель;
- поставщик;
- партия;
- текущий остаток в граммах;
- минимальный остаток;
- закупочная цена за килограмм;
- средневзвешенная цена за килограмм;
- дата поступления;
- место хранения;
- примечание.

## 3. Приход провода

Пользователь вводит:

- складскую позицию;
- массу поступления;
- цену за килограмм;
- поставщика;
- номер партии или накладной;
- дату;
- комментарий.

После подтверждения остаток увеличивается, а операция сохраняется в журнале движения.

## 4. Списание провода

Провод списывается на конкретный ремонт и конкретную группу обмоток.

Пользователь указывает:

- двигатель;
- ремонт;
- тип обмотки: рабочая, пусковая, вспомогательная;
- складскую позицию провода;
- фактическую массу использованного провода;
- число жил;
- комментарий.

После подтверждения:

- остаток уменьшается;
- стоимость материала рассчитывается автоматически;
- запись привязывается к ремонту и карточке двигателя;
- история движения остается неизменяемой.

## 5. Расчет стоимости

Формула:

```text
стоимость = масса_грамм × цена_за_кг / 1000
```

Пример:

```text
Масса: 2 350 г
Цена: 980 сом/кг
Стоимость: 2 303 сом
```

В базе денежные значения хранятся целыми числами в минимальных денежных единицах. Расчеты выполняются целочисленно с контролируемым округлением.

## 6. Масса обмотки в карточке двигателя

Карточка двигателя должна содержать:

- общую массу провода;
- массу рабочей обмотки;
- массу пусковой обмотки;
- массу вспомогательной обмотки;
- фактически использованный провод;
- диаметр;
- число жил;
- стоимость материала;
- источник значения массы: измерено или рассчитано;
- дату измерения;
- историю изменений.

Значения массы сохраняются отдельно для каждого ремонта, поскольку при последующей перемотке параметры могут измениться.

## 7. Страница склада

Основные разделы:

### Остатки

- список проводов;
- фильтр по диаметру, материалу и марке;
- текущая масса;
- минимальный остаток;
- стоимость остатка;
- предупреждение о недостатке.

### Приход

- форма поступления;
- история приходов;
- поставщики и партии.

### Списание

- списание на ремонт;
- возврат остатка;
- корректировка после взвешивания.

### Движение

- полный журнал операций;
- фильтры по дате, проводу, ремонту и клиенту;
- запрет физического удаления подтвержденных операций;
- корректировки выполняются отдельной обратной записью.

### Инвентаризация

- ввод фактической массы;
- сравнение с расчетным остатком;
- создание корректирующей операции;
- сохранение причины расхождения.

## 8. Связь с ремонтом и двигателем

Цепочка данных:

```text
Складская позиция
        ↓
Списание провода
        ↓
Группа обмоток
        ↓
Ремонт
        ↓
Двигатель
        ↓
Клиент
```

Открыв карточку двигателя, пользователь видит, какой провод применялся, его диаметр, число жил, массу и стоимость для каждого ремонта.

## 9. Контроль ошибок

- запрещено списывать отрицательную массу;
- предупреждение при недостаточном остатке;
- списание сверх остатка требует отдельного подтверждения администратора;
- одна операция не должна применяться дважды;
- каждая операция получает уникальный ID;
- после внезапного отключения питания остаток восстанавливается из журнала движений;
- резервное копирование включает складские позиции и все движения.

## 10. Будущие возможности

- учет лака, изоляции, подшипников и других материалов;
- расчет общей себестоимости ремонта;
- статистика расхода по диаметрам;
- отчет по остаткам и стоимости склада;
- печать этикеток и QR-кодов партий;
- поддержка электронных весов через отдельный интерфейс.
