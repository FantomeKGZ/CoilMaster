# Откат остатка при ошибке списания материала

## Исправленная проблема

Ранее `MaterialLedger::confirmUsage()` сначала уменьшал остаток материала в
`/data/materials/materials.ndjson`, а затем записывал подтверждённое использование в
`/data/materials/usage.ndjson`.

Если файл истории не удавалось открыть или полностью записать, остаток уже оставался уменьшенным без подтверждённой записи использования.

## Новое поведение

После уменьшения остатка система пытается добавить строку истории использования.

Если:

- файл `usage.ndjson` не открылся;
- записано меньше байтов, чем содержит сформированная строка;

система вызывает `restoreQuantity()` и возвращает списанное количество обратно в карточку материала.

Таким образом обычная ошибка открытия или записи журнала больше не приводит к безвозвратному уменьшению складского остатка.

## Ограничение

Это компенсирующий откат при обнаруженной ошибке записи. Защита от внезапного отключения питания между операциями требует отдельного транзакционного журнала восстановления и будет реализована следующим этапом.
