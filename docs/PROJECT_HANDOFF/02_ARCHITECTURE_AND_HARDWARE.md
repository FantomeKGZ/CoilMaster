# Архитектура и аппаратная часть

## Зафиксированная архитектура

Система разделена на два независимых контроллера.

### Arduino Uno

Arduino отвечает за всё, что связано с реальным временем, физическим управлением и безопасностью:

- счёт импульсов датчика Холла;
- управление процессом намотки;
- работа клавиатуры 4×4;
- физическая кнопка START;
- управление SSR;
- звуковые сигналы;
- локальные состояния станка;
- выполнение задания, полученного от ESP32;
- отправка событий запуска и завершения.

### ESP32

ESP32 отвечает за сервисный уровень:

- веб-интерфейс;
- Wi‑Fi;
- microSD;
- RTC DS3231;
- клиенты, двигатели и ремонты;
- склад провода и материалов;
- калькуляцию;
- журналирование;
- подготовку и доставку задания Arduino;
- отображение статуса оператора.

ESP32 не является контроллером безопасности и не должна напрямую управлять SSR.

## Жёсткие правила безопасности

1. Удалённый запрос с ESP32 не имеет права напрямую включить SSR.
2. Каждая катушка запускается только после физического подтверждения на Arduino.
3. Одновременно выполняется только одна программа намотки.
4. До завершения текущего запуска новый запуск в той же сессии запрещён.
5. Кнопка `B` означает отмену/возврат, а не аварийную перезагрузку контроллера.
6. После промежуточной катушки подаётся один средний звуковой сигнал.
7. После полного завершения программы подаются три коротких сигнала.
8. При ошибке связи Arduino должна оставаться в безопасном состоянии; отсутствие подтверждения не является разрешением запуска.
9. Общая земля Arduino, ESP32 и преобразователя уровней обязательна.

## Arduino Uno — закреплённые подключения

| Назначение | Пин Arduino |
|---|---|
| Клавиатура 4×4 | D2–D9 |
| Физический START | D10 |
| Buzzer | D11 |
| SSR | D12 |
| Датчик Холла | A0 |
| SoftwareSerial TX | A1 |
| SoftwareSerial RX | A2 |

Датчик Холла остаётся на Arduino и не переносится на ESP32.

## ESP32 — закреплённые подключения

### UART2

| Назначение | GPIO ESP32 |
|---|---:|
| RX2 | GPIO16 |
| TX2 | GPIO17 |

Связь с Arduino выполняется через преобразователь логических уровней.

### microSD

| Сигнал | GPIO ESP32 |
|---|---:|
| CS | GPIO5 |
| SCK/CLK | GPIO18 |
| MISO | GPIO19 |
| MOSI | GPIO23 |

### RTC DS3231

| Сигнал | GPIO ESP32 |
|---|---:|
| SDA | GPIO21 |
| SCL | GPIO22 |

Питание конкретных модулей DS3231 и microSD выбирать по маркировке платы и наличию стабилизатора. Нельзя автоматически считать любой модуль безопасным для любого напряжения.

## Преобразователь уровней

Для UART используется двунаправленный преобразователь уровней, проверенный в аппаратном тесте.

Общие правила:

- сторона LV — 3.3 V ESP32;
- сторона HV — 5 V Arduino;
- общий GND;
- ESP32 TX подключается к Arduino RX через соответствующий канал;
- Arduino TX подключается к ESP32 RX через соответствующий канал.

## Питание и соединение плат

Нельзя соединять платы только на основании того, что обе платы или платы расширения имеют вывод `5V`.

При интеграции обязательно учитывать:

- общий GND;
- допустимые логические уровни GPIO;
- отдельное питание нагрузки и логики;
- ток потребления модулей;
- обратное питание через USB или стабилизаторы;
- безопасное состояние SSR при загрузке и перезапуске.

## Что уже аппаратно проверено

Пользователь ранее подтвердил:

- проверку основных модулей;
- тест ESP32 + DS3231;
- тест microSD и других модулей;
- обмен данными ESP32 ↔ Arduino;
- работу преобразователя уровней;
- рабочую скорость UART.

Не повторять эти тесты без новой причины, связанной с интеграцией или обнаруженной неисправностью.

## Архитектурный порядок разработки

Принят порядок:

1. спецификация;
2. архитектурное решение;
3. реализация небольшого законченного изменения;
4. компиляция;
5. автоматические тесты;
6. проверка на оборудовании, когда требуется;
7. документация;
8. фиксация результата в handoff-журнале.

Разделение проекта должно сохраняться по смыслу:

- Core;
- Hardware;
- Network;
- Database/Storage;
- Test Center.

Нельзя смешивать веб-логику с прямым управлением физическим оборудованием.
