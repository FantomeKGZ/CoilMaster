# Метаданные формулы стоимости дополнительных материалов

Успешный ответ `POST /api/materials/usage` дополнительно описывает способ формирования стоимости операции:

```json
{
  "line_cost_minor": 138,
  "line_cost_source": "PERSISTED_USAGE_SNAPSHOT",
  "line_cost_formula": "ROUND(quantity_milli*unit_price_minor/1000)",
  "value_rounding": "NEAREST_MINOR_UNIT",
  "historical_cost_policy": "USE_PERSISTED_LINE_COST"
}
```

## Формула

Для новых операций стоимость рассчитывается сервером ESP32:

```text
(quantity_milli × unit_price_minor + 500) / 1000
```

Промежуточное умножение выполняется в `uint64_t`. Добавление `500` обеспечивает округление до ближайшей минимальной денежной единицы.

## Историческая стоимость

Поле `line_cost_minor` сохраняется внутри записи расхода. При последующем изменении складской цены старые операции не пересчитываются.

Калькуляция ремонта должна использовать сохранённый `line_cost_minor`, а не заново умножать историческое количество на текущую цену материала.

## Назначение метаданных

- `line_cost_source` указывает, что стоимость является снимком операции;
- `line_cost_formula` делает формулу доступной клиентскому интерфейсу и диагностике;
- `value_rounding` фиксирует правило округления;
- `historical_cost_policy` запрещает неявный пересчёт старых расходов по новой цене.

## Совместимость

Формат запроса и существующие поля ответа не изменены. Добавленные поля являются расширением API.
