# Общий каталог двигателей и связь с ремонтом

## Изменение модели

Двигатель больше не хранится как текст внутри ремонта. Создан общий каталог технологических карточек двигателей.

Файлы microSD:

- `/data/workshop/clients.ndjson`;
- `/data/workshop/motors.ndjson`;
- `/data/workshop/repairs.ndjson`.

## Минимальная карточка двигателя

Обязательны:

- `name` — название двигателя;
- `coil_program` — хотя бы одна программа катушек.

Остальные характеристики будут добавляться как необязательные поля.

## API двигателей

- `GET /api/motors`;
- `GET /api/motors?name=...`;
- `POST /api/motors`.

Создание:

- `name`;
- `coil_program`;
- `comment` — необязательно.

## Создание ремонта

`POST /api/repairs`

Теперь требует:

- `client_id`;
- `motor_id`;
- `received_at`;
- `complaint` — необязательно;
- `comment` — необязательно.

Перед записью проверяется существование и клиента, и двигателя.

## Связи

Один клиент может иметь много ремонтов. Одна карточка двигателя может использоваться во многих ремонтах разных клиентов. Ремонт является связью клиента и двигателя и получает собственный `repair_id`.

## Следующий шаг

Обновить мобильную и ПК-страницы ремонтов: добавить создание и поиск карточки двигателя, выбор `motor_id`, а затем открытие калькуляции, списания провода и материалов из выбранного ремонта.
