# CoilMaster — модель данных

## Иерархия

```text
Client
  └── Motor
       └── Repair
            ├── WindingGroup
            │    └── WindingRun
            ├── Materials
            ├── Attachments
            └── Notes

WarehouseItem
  └── StockMovement
       └── RepairMaterialUsage
```

## Client

Поля:

- `client_id`;
- ФИО или название организации;
- телефон;
- WhatsApp;
- адрес;
- примечания;
- дата создания и изменения;
- статус: активный/архивный.

## Motor

Поля:

- `motor_id`;
- `client_id` текущего владельца;
- название и модель;
- производитель;
- серийный номер;
- 1‑фазный или 3‑фазный;
- мощность, напряжение, ток, обороты;
- количество пазов;
- фотографии и схемы;
- примечания;
- история владельцев и изменений.

### Масса обмотки двигателя

Для двигателя и отдельных типов обмотки должны храниться значения массы провода:

- общая масса провода двигателя;
- масса рабочей обмотки;
- масса пусковой обмотки;
- масса вспомогательной обмотки, если она имеется;
- единица измерения: граммы или килограммы;
- признак `measured` или `estimated`;
- дата измерения;
- комментарий к измерению.

Масса должна храниться в целых граммах (`uint32` на уровне обмена и целое число в базе), чтобы избежать ошибок округления с плавающей точкой.

## Repair

Один двигатель может иметь много ремонтов.

Поля:

- `repair_id`;
- `motor_id`;
- дата приема;
- дата завершения;
- описание неисправности;
- выполненные работы;
- статус ремонта;
- мастер и примечания.

## WindingGroup

Группа объединяет операции, относящиеся к одной части ремонта.

Примеры:

- рабочая обмотка `50/50/50`, выполненная два раза;
- пусковая обмотка `40/30`;
- комплект для одного 1‑фазного двигателя;
- набор одинаковых рабочих обмоток для 3‑фазного двигателя.

Поля:

- `group_id`;
- `repair_id`;
- тип: `WORKING`, `STARTING`, `AUXILIARY`, `OTHER`;
- последовательность витков;
- требуемое число повторов;
- выполненное число повторов;
- диаметр провода;
- число жил;
- материал и марка провода;
- масса использованного провода в граммах;
- цена материала на момент списания;
- шаг и схема укладки;
- комментарий.

## WindingRun

Каждый фактический запуск Arduino сохраняется отдельно.

Поля:

- `job_id`;
- дата и время RTC;
- источник: Arduino или WEB;
- последовательность заданных витков;
- последовательность фактических витков;
- статус каждой катушки;
- итоговый статус;
- связь с `group_id`, если операция уже классифицирована;
- флаг синхронизации.

## WarehouseItem

Складская позиция провода.

Поля:

- `item_id`;
- категория: `WIRE`;
- марка провода;
- материал: медь или алюминий;
- диаметр;
- число жил по умолчанию;
- производитель и поставщик;
- текущий остаток в граммах;
- минимальный остаток в граммах;
- цена закупки за килограмм;
- средневзвешенная цена за килограмм;
- место хранения;
- номер партии;
- дата поступления;
- комментарий;
- статус: активный/архивный.

## StockMovement

Каждое изменение остатка хранится отдельной неизменяемой записью.

Типы движения:

- `RECEIPT` — приход;
- `WRITE_OFF` — списание на ремонт;
- `ADJUSTMENT_PLUS` — корректировка вверх;
- `ADJUSTMENT_MINUS` — корректировка вниз;
- `RETURN` — возврат материала;
- `INVENTORY` — результат инвентаризации.

Поля:

- `movement_id`;
- `item_id`;
- дата и время RTC;
- масса в граммах;
- цена за килограмм на момент операции;
- итоговая стоимость движения;
- связанный `repair_id`;
- связанный `group_id`;
- пользователь или источник операции;
- причина и комментарий.

## RepairMaterialUsage

Связывает ремонт с фактически использованным проводом.

Поля:

- `usage_id`;
- `repair_id`;
- `group_id`;
- `item_id`;
- тип обмотки;
- масса списания в граммах;
- цена за килограмм на момент списания;
- рассчитанная стоимость;
- число жил;
- диаметр;
- дата списания;
- статус подтверждения.

Стоимость рассчитывается по массе:

```text
стоимость = масса_грамм × цена_за_кг / 1000
```

Все денежные значения хранятся в минимальных денежных единицах, например в тыйынах, без использования `float`.

## Агрегация

ESP32 может показывать одинаковые завершенные операции за выбранный период как одну строку:

```text
50/50/50 — выполнено 2 раза сегодня
40/30 — выполнено 1 раз сегодня
```

При этом исходные `WindingRun` не объединяются физически и остаются в журнале. Пользователь может связать несколько операций с одним `WindingGroup`, ремонтом и двигателем.

## Хранение

Рекомендуемая структура microSD:

```text
/data/clients/
/data/motors/
/data/repairs/
/data/winding-groups/
/data/winding-runs/
/data/warehouse/items/
/data/warehouse/movements/
/data/warehouse/usage/
/data/indexes/
/backups/
/logs/
```

Для первой версии допускаются версионированные JSON/NDJSON-файлы с индексами. Запись выполняется через временный файл и безопасную замену. Формат каждой сущности содержит `schema_version`.
