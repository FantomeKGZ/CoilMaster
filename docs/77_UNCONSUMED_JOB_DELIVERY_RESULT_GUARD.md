# Защита непрочитанного результата доставки задания

## Проблема

`UartEventReceiver` хранит результат доставки задания до вызова
`takeJobDelivery()`.

До этого изменения новое задание можно было поставить в очередь сразу после
получения `ACCEPTED`, `REJECTED` или `TimedOut`, даже если предыдущий результат
ещё не был прочитан управляющим кодом. При быстром завершении следующей
доставки старый результат мог быть перезаписан.

## Новое правило

`queueJob()` возвращает `false`, пока выполняется хотя бы одно из условий:

- предыдущее задание ещё ожидает подтверждения;
- существует непрочитанный `JobDeliveryEvent`;
- новое задание не прошло проверку `OutgoingWindingJob::isValid()`.

Новое задание разрешается только после того, как управляющий код вызвал:

```cpp
JobDeliveryEvent delivery;
receiver.takeJobDelivery(delivery);
```

## Гарантия

Для каждого завершённого цикла доставки сохраняется ровно один результат:

- `Accepted`;
- `Rejected`;
- `TimedOut`.

Результат, `jobId` и число попыток не могут быть молча заменены результатом
следующего задания.

## Совместимость

Формат UART-кадров и публичные C++-сигнатуры не изменены. Усилено только
условие допуска нового задания в очередь.
