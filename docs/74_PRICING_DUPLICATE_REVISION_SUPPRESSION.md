# Подавление одинаковых редакций цены

`POST /api/repairs/costing` теперь не добавляет новую строку в журнал `/data/repairs/pricing.ndjson`, если переданные значения полностью совпадают с текущей активной ценой.

Сравниваются:

- `labour_cost_minor`;
- `client_price_minor`;
- `currency`.

Проверка выполняется только после проверки `expected_revision`. Поэтому устаревший клиент по-прежнему получает `409 pricing_revision_conflict`, даже если случайно отправил значения, совпадающие с более старой локальной копией.

## Ответ без новой редакции

```json
{
  "saved": false,
  "unchanged": true,
  "current_revision": 5,
  "new_revision": 5,
  "revision_source": "APPEND_ONLY_LOG"
}
```

`new_revision` сохраняется в ответе для совместимости с текущим мобильным и настольным интерфейсом. Номер не увеличивается, timestamp не меняется, новая запись в журнал не создаётся.

## Ответ при фактическом изменении

```json
{
  "saved": true,
  "unchanged": false,
  "previous_revision": 5,
  "new_revision": 6,
  "revision_source": "APPEND_ONLY_LOG"
}
```

## Назначение

Механизм предотвращает:

- появление нескольких одинаковых редакций при повторном нажатии кнопки;
- рост журнала без фактического изменения цены;
- ложное обновление времени последней редакции;
- искажение истории действий оператора.
