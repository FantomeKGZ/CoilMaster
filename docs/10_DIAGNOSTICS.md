# CoilMaster — диагностика и recovery

## Назначение

Диагностика доступна локально на Arduino и через Web-интерфейс ESP32. Опасные тесты не выполняются без физического подтверждения возле станка. Recovery-функции не должны подменять фактический результат намотки.

## Калибровка Hall SS49E

Web-страница отображает:

- текущее `analogRead(A0)`;
- минимальное и максимальное значение за период;
- текущий порог;
- гистерезис;
- число обнаруженных импульсов;
- состояние магнита.

Новый порог передается Arduino, проверяется по допустимому диапазону и сохраняется только после явного подтверждения.

## Проверки узлов

### Клавиатура

Проверяются отдельные клавиши и отсутствие ложных повторов. Специальная recovery-последовательность `D → * → # → D` должна тестироваться отдельно от обычного управления.

### LCD1602

Вывод тестовых строк и проверка подсветки без нарушения активной намотки.

### Hall

Живое значение, порог, гистерезис и тестовый счет импульсов.

### Зуммер

Короткий ограниченный сигнал. Длительные блокирующие последовательности запрещены.

### UART/CMP1

Проверяются:

- физическая связь ESP32 ↔ Arduino;
- CRC;
- `JOB` → `JOB_ACK`;
- retry при потерянном ACK;
- `JOB_CANCEL` → `JOB_CANCEL_ACK`;
- идемпотентная отмена уже очищенного remote job;
- `RUN_STARTED` / `RUN_COMPLETED`;
- reboot/recovery correlation;
- `ALL_CLEAR` fallback.

## Recovery зависшего задания

Сценарий применяется, если ESP32 показывает незакрытое задание, а Arduino его не отображает, либо потерян ACK и неизвестно, получила ли Arduino `JOB`.

### Нормальный путь

Сначала использовать Web/API cancel. ESP32 должна:

1. остановить дальнейший `JOB` retry;
2. при возможной предыдущей доставке отправить `JOB_CANCEL`;
3. дождаться положительного `JOB_CANCEL_ACK`;
4. закрыть persisted no-run state.

### Физический fallback

Если normal cancel не может завершить синхронизацию, на Arduino используется:

```text
D → * → # → D
```

Условия безопасности:

- не использовать во время активной или paused намотки;
- remote job с run evidence не должен очищаться;
- комбинация не включает SSR;
- комбинация не создает `RUN_COMPLETED`;
- комбинация не выполняет wire writeoff.

При безопасном результате Arduino отправляет:

```text
CMP1|JOB_CANCEL_ACK|0|CANCELLED|ALL_CLEAR|C|<CRC>
```

ESP32 должен связать этот signal с текущим/recovered persisted job и закрыть его через обычный audited cancel path.

## Рекомендуемый hardware regression для JOB recovery

1. Прошить Arduino и ESP32 из одной актуальной точки `cmp-protocol-v1`.
2. Проверить обычный `JOB → JOB_ACK ACCEPTED`.
3. Создать тест, где ACK намеренно не доходит до ESP32, затем выполнить cancel.
4. Убедиться, что Arduino очищает exact no-run job и ESP32 закрывает persisted state.
5. Повторить `JOB_CANCEL` после уже выполненной очистки — состояние должно оставаться согласованным.
6. Проверить reboot ESP32 при незакрытом no-run job.
7. Выполнить `D → * → # → D` и убедиться в `ALL_CLEAR`.
8. Отдельно убедиться, что fallback блокируется во время активной намотки.
9. Проверить, что ни один recovery-сценарий не создает automatic wire writeoff.

## RTC DS3231

Проверяются время, дата, статус модуля и признак потери питания.

## microSD

Проверяются наличие карты, емкость, свободное место, чтение production data, backup integrity и recovery evidence. Destructive fault injection выполняется только на disposable карте/образе.

## SSR

Любая диагностика SSR обязана сохранять физический safety boundary. Web не должен напрямую включать SSR. Любое нарушение состояния/связи должно оставлять выход выключенным.

## Журнал диагностики

ESP32 сохраняет результат теста и диагностические коды настолько, насколько это предусмотрено текущей production persistence. Диагностические записи не должны превращать неопределенный результат в успешное завершение работы.
