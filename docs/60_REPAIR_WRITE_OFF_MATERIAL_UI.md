# Материал-зависимое списание провода из ремонта

Обновлены страницы:

- `firmware/esp32/web/mobile/writeoff.html`;
- `firmware/esp32/web/desktop/writeoff.html`.

## Выбор бухты

Форма списания загружает активные бухты через:

`GET /api/warehouse/spools?material=ALL|CU|AL`

Оператор может показать:

- все бухты;
- только медные;
- только алюминиевые.

В подписи каждой бухты отображаются:

- номер;
- материал;
- диаметр;
- текущий остаток.

## Проверки перед списанием

Интерфейс не отправляет запрос, если:

- ремонт не выбран;
- бухта не выбрана;
- материал бухты имеет класс `UNKNOWN`;
- вес введён некорректно;
- вес после работы не меньше веса до работы;
- вес до работы не совпадает с текущим остатком бухты, полученным от ESP32.

Последняя проверка сохраняет серверный остаток как авторитетное значение и уменьшает риск списания по устаревшим данным.

## Старые бухты

Бухта с `material_class=UNKNOWN` остаётся видимой в режиме `Все`, но её списание блокируется интерфейсом. Оператору предлагается сначала назначить материал на странице склада.

Backend по-прежнему остаётся последней линией проверки и не полагается только на JavaScript.

## Подтверждение

После успешного `POST /api/warehouse/write-offs` интерфейс показывает:

- списанную массу;
- материал из поля `wire_type` ответа;
- новый остаток бухты.

Затем список бухт загружается повторно, чтобы форма использовала актуальный вес.
