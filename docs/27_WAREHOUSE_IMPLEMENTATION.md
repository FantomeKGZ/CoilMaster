# Этап 27 — реализация склада провода

## Цель первого этапа

Первая реализация склада создаёт серверный модуль ESP32, который собирает сведения по диаметрам провода:

- общий фактический остаток;
- количество активных бухт;
- подтверждённый расход за текущий месяц;
- подтверждённый расход за всё время.

## Файлы microSD

### `/data/warehouse/spools.ndjson`

Одна строка описывает конкретную бухту:

```json
{"schema_version":1,"spool_id":12,"diameter_hundredths_mm":80,"current_weight_g":13420,"status":"ACTIVE"}
```

Диаметр хранится в сотых долях миллиметра:

- `50` = 0,50 мм;
- `63` = 0,63 мм;
- `80` = 0,80 мм;
- `100` = 1,00 мм.

Масса хранится в целых граммах.

### `/data/warehouse/movements.ndjson`

Подтверждённое фактическое списание после повторного взвешивания бухты:

```json
{"schema_version":1,"movement_id":45,"type":"WRITE_OFF","diameter_hundredths_mm":80,"mass_g":5120,"timestamp":"2026-08-05T12:00:00","status":"CONFIRMED","repair_id":154}
```

Только движения `WRITE_OFF` со статусом `CONFIRMED` входят в расход на ремонты.
Инвентаризационные корректировки и потери должны учитываться отдельно.

## Новый модуль ESP32

Добавлены:

```text
firmware/esp32/src/CM_WarehouseStore.h
firmware/esp32/src/CM_WarehouseStore.cpp
```

`WarehouseStore`:

1. создаёт каталог `/data/warehouse`;
2. читает остатки всех активных бухт;
3. группирует их по диаметру;
4. суммирует подтверждённые списания;
5. возвращает агрегаты для будущего API и страницы «Склад».

## Представление в WEB

Главная страница склада должна выводить строки вида:

```text
Диаметр   Остаток      Бухт   За месяц   За всё время
0,50 мм   8,420 кг     2      3,420 кг   74,630 кг
0,63 мм   15,760 кг    3      8,700 кг   152,480 кг
0,80 мм   42,560 кг    4      21,560 кг  348,910 кг
```

При выборе диаметра открывается список конкретных бухт и история их взвешиваний.
