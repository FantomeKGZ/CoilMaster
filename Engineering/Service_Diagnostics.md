# CoilMaster — сервис, калибровка и диагностика

## 1. Общие принципы

Сервисные функции доступны:

- локально через меню Arduino Uno и LCD1602;
- удаленно через WEB-интерфейс ESP32.

ESP32 отображает и передает команды, но фактические проверки исполнительных устройств выполняет Arduino Uno.

Опасные действия должны требовать явного подтверждения и выполняться только в безопасном состоянии станка.

## 2. Калибровка датчика Холла SS49E

### 2.1 Назначение

Калибровка позволяет подобрать порог срабатывания датчика без перепрошивки Arduino Uno.

### 2.2 Данные от Arduino

Arduino передает ESP32:

- текущее значение `analogRead(A0)`;
- минимальное наблюдаемое значение;
- максимальное наблюдаемое значение;
- текущий порог срабатывания;
- величину гистерезиса;
- состояние обнаружения магнита;
- количество зарегистрированных импульсов за тест.

### 2.3 WEB-интерфейс

Экран калибровки показывает:

- текущее аналоговое значение;
- график или шкалу изменения сигнала;
- текущий порог;
- гистерезис;
- индикатор `MAGNET DETECTED`;
- кнопки начала и остановки теста;
- сохранение нового порога после подтверждения.

### 2.4 Безопасность

- изменение порога разрешено только при остановленном SSR;
- тестовый счет импульсов не изменяет рабочий журнал намоток;
- новое значение применяется только после проверки диапазона;
- при недопустимом значении Arduino отклоняет команду;
- после сохранения Arduino возвращает фактически примененное значение.

## 3. Диагностика клавиатуры 4×4

WEB-экран отображает:

- последнюю нажатую клавишу;
- состояние всех клавиш по мере нажатия;
- счетчик событий;
- результат теста матрицы.

Диагностика не должна запускать обычные команды `A/B/C/D/*/#`. В тестовом режиме нажатия только отображаются.

## 4. Диагностика LCD1602

Arduino выполняет тестовую последовательность:

- очистка экрана;
- включение подсветки;
- вывод теста в обе строки;
- проверка доступности I²C-адреса;
- отображение результата теста.

WEB-интерфейс показывает:

- статус I²C;
- обнаруженный адрес;
- результат тестовой команды;
- текст, который должен отображаться на LCD.

## 5. Диагностика SS49E

Проверяются:

- наличие аналогового сигнала;
- значение покоя;
- изменение сигнала при прохождении магнита;
- работа порога и гистерезиса;
- отсутствие многократного счета одного прохождения.

## 6. Диагностика SSR-40DA

### Ограничения

Тест SSR потенциально включает нагрузку 220 В и является опасным.

Требования:

- тест доступен только при остановленной намотке;
- перед включением требуется локальное подтверждение на Arduino;
- WEB-интерфейс не включает SSR единственным нажатием;
- включение ограничено коротким тестовым интервалом;
- Arduino автоматически выключает SSR по тайм-ауту;
- при потере связи SSR выключается Arduino независимо от ESP32.

WEB-интерфейс отображает:

- запрошенное состояние;
- подтвержденное состояние Arduino;
- оставшееся время теста;
- причину отказа, если тест запрещен.

## 7. Диагностика активного зуммера

Поддерживаются:

- одиночный короткий сигнал;
- три сигнала завершения катушки;
- тест включения/выключения;
- подтверждение выполнения от Arduino.

Тест не должен использовать блокирующие задержки в основном цикле.

## 8. Диагностика UART Arduino Uno ↔ ESP32

Проверяются:

- наличие связи;
- версия CMP Protocol;
- время последнего принятого пакета;
- количество принятых пакетов;
- ошибки CRC;
- ошибки формата;
- повторные пакеты;
- потерянные подтверждения;
- задержка запроса-ответа;
- количество переполнений RX-буфера.

Рекомендуется команда `PING/PONG` с уникальным счетчиком и временем отправки.

## 9. Диагностика RTC DS3231

ESP32 проверяет:

- доступность DS3231 по I²C;
- текущую дату и время;
- признак потери питания часов;
- корректность диапазонов даты и времени;
- возможность чтения и установки времени;
- состояние батарейки, если поддерживается используемым модулем и библиотекой.

WEB-интерфейс позволяет:

- посмотреть время RTC;
- сравнить с временем браузера;
- синхронизировать после подтверждения;
- увидеть предупреждение о недействительном времени.

## 10. Сводный экран диагностики

Главный диагностический экран содержит таблицу:

| Узел | Статус | Последняя проверка | Подробности |
|---|---|---|---|
| Arduino Uno | OK / ERROR / OFFLINE | дата и время | версия прошивки |
| UART CMP | OK / DEGRADED / ERROR | дата и время | CRC, потери, задержка |
| LCD1602 | OK / ERROR | дата и время | I²C-адрес |
| Keypad 4×4 | OK / TEST | дата и время | последняя клавиша |
| SS49E | OK / CALIBRATION / ERROR | дата и время | значение и порог |
| SSR-40DA | OFF / ON / BLOCKED | дата и время | причина блокировки |
| Buzzer | OK / ERROR | дата и время | последний тест |
| microSD | OK / READONLY / ERROR | дата и время | свободное место |
| RTC DS3231 | OK / INVALID / ERROR | дата и время | текущее время |

## 11. Журнал диагностики

ESP32 сохраняет на microSD:

- время события;
- узел;
- код события;
- результат;
- дополнительные параметры;
- версию прошивки Arduino и ESP32.

Журнал не должен бесконтрольно расти. Требуется ротация файлов или ограничение размера.

## 12. Требования к CMP-командам сервиса

Прикладной слой должен предусмотреть команды для:

- чтения значения Hall;
- установки порога Hall;
- запуска и остановки режима калибровки;
- чтения состояния входов и выходов;
- теста LCD;
- теста клавиатуры;
- безопасного теста SSR;
- теста зуммера;
- чтения диагностических счетчиков;
- запроса версии и возможностей устройства.

Все команды изменения должны возвращать явное подтверждение или причину отказа.
