# Проверка ремонта при списании дополнительных материалов

`POST /api/materials/usage` теперь принимает списание только для ремонта, который существует в реестре мастерской.

## Поведение API

Если `repair_id` корректен по формату, но такого ремонта нет в `/data/workshop/repairs.ndjson`, сервер возвращает:

```json
{
  "error": "repair_not_found"
}
```

HTTP-статус: `404`.

Остаток материала при этом не изменяется, запись использования не создаётся и pending-транзакция не запускается.

При успешном списании ответ дополнительно содержит:

```json
{
  "confirmed": true,
  "repair_id": 28,
  "repair_reference_validated": true
}
```

## Зачем это нужно

Проверка не позволяет создать расход материала, который невозможно связать с реальной карточкой ремонта. Это сохраняет согласованность между:

- реестром ремонтов;
- журналом расхода дополнительных материалов;
- калькуляцией себестоимости ремонта.

## Реализация

`MaterialLedger::repairExists()` читает реестр ремонтов и ищет точное совпадение `repair_id`. Значение не считается существующим только потому, что оно больше нуля.
