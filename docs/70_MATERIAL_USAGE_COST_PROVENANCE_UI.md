# Проверка происхождения стоимости расхода материалов в интерфейсе

Мобильная и настольная страницы списания дополнительных материалов проверяют успешный ответ `POST /api/materials/usage` перед показом подтверждения оператору.

Проверяются поля:

- `repair_reference_validated == true`;
- возвращённый `repair_id` совпадает с выбранным ремонтом;
- возвращённый `material_id` совпадает с выбранным материалом;
- возвращённый `quantity_milli` совпадает с отправленным количеством;
- `line_cost_source == "PERSISTED_USAGE_SNAPSHOT"`;
- `value_rounding == "TRUNCATE_MINOR_UNIT"`.

При полном совпадении интерфейс сообщает, что цена и стоимость сохранены в снимке операции ESP32.

Если запись была создана, но хотя бы одно поле подтверждения отсутствует или не совпадает, интерфейс не выдаёт обычное зелёное подтверждение. Вместо этого показывается предупреждение и обновляется каталог материалов, чтобы оператор мог проверить остаток и калькуляцию.

Это не отменяет уже подтверждённую сервером операцию и не пытается повторно отправить списание.

Изменённые файлы:

- `firmware/esp32/web/mobile/materials.html`;
- `firmware/esp32/web/desktop/materials.html`.
