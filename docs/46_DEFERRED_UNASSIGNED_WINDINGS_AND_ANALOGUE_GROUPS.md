# Отложенная реализация: неразобранные намотки и группы аналогов

Этот документ фиксирует согласованную архитектуру для последующей реализации.

## Неразобранные намотки

Программа, введённая на клавиатуре Arduino, после выполнения должна передаваться на ESP32 полным снимком и сохраняться со статусом `UNASSIGNED`.

Хранятся два уровня:

- карточка программы с агрегированным счётчиком;
- отдельная история каждого запуска.

Одинаковые программы группируются по техническому ключу, но отдельные запуски не теряются.

Отдельные страницы:

- `/mobile/unassigned-windings.html`;
- `/desktop/unassigned-windings.html`.

Страница должна поддерживать чекбоксы и массовые действия: привязка к ремонту, создание двигателя, добавление к существующему двигателю, создание/выбор группы аналогов, обработка и логическое удаление.

## Сравнение программ и обмоток

Совпадение только витков не является дублем двигателя.

Нужны отдельные ключи:

- ключ программы витков;
- ключ полной спецификации обмотки с материалом, диаметрами и количеством параллельных жил;
- признаки двигателя: название, модель, производитель и теги.

Разные провода при одинаковых витках сохраняются как отдельные варианты обмотки.

## Двигатели-клоны и аналоги

Конкретные двигатели остаются отдельными карточками и различаются полями:

- название;
- модель;
- производитель;
- теги.

Похожие двигатели могут входить в одну группу аналогов и использовать общий вариант обмотки.

Для статистики желательно хранить:

- счётчик конкретного двигателя;
- общий счётчик варианта обмотки или группы аналогов.

Название, модель и теги используются для поиска и различения карточек, но не определяют техническую идентичность обмотки.

Автоматическое объединение запрещено: система только показывает совпадения, окончательное решение принимает оператор.
