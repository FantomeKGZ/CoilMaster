# Строгая проверка полей событий UART

ESP32 принимает события Arduino только в точном формате:

```text
CMP1|EVT|<TYPE>|<SESSION_ID>|<RUN_ID>|<COMPLETED_RUNS>|<CRC16>
```

## Числовые поля

Поля `SESSION_ID`, `RUN_ID` и `COMPLETED_RUNS` должны:

- состоять только из десятичных цифр;
- не содержать знака, пробелов, суффиксов или лишних символов;
- помещаться в целевой тип;
- иметь ненулевые `SESSION_ID` и `RUN_ID`.

Диапазоны:

- `SESSION_ID`: `1..4294967295`;
- `RUN_ID`: `1..4294967295`;
- `COMPLETED_RUNS`: `0..65535`.

Строки вроде `12abc`, `-1`, `+7`, пустое поле или число с переполнением отклоняются.

## Семантика событий

Для `RUN_STARTED` требуется:

```text
COMPLETED_RUNS = 0
```

Для `RUN_COMPLETED` требуется:

```text
COMPLETED_RUNS > 0
```

Это не позволяет принять завершение без фактически выполненной катушки и не позволяет передать счётчик завершений в событии старта.

## Структура кадра

После поля `COMPLETED_RUNS` не допускаются дополнительные поля перед CRC. CRC16 по-прежнему проверяется до разбора содержимого.

## JOB_ACK

`job_id` в ответе Arduino теперь разбирается тем же строгим десятичным парсером. Ответ с повреждённым или переполненным идентификатором не завершает ожидающую доставку задания.
