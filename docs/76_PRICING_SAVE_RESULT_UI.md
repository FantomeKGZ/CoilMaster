# Отображение результата сохранения цены

Мобильная и настольная страницы калькуляции теперь различают все серверные результаты `POST /api/repairs/costing`.

## Новая редакция

При ответе:

```json
{
  "saved": true,
  "unchanged": false,
  "write_performed": true,
  "revision_advanced": true,
  "new_revision": 6
}
```

интерфейс сообщает, что создана редакция №6, и повторно загружает калькуляцию и историю.

## Данные не изменились

При ответе:

```json
{
  "saved": false,
  "unchanged": true,
  "write_performed": false,
  "revision_advanced": false,
  "current_revision": 5
}
```

интерфейс явно сообщает, что изменений нет и новая запись журнала не создавалась.

## Конфликт редакций

При `pricing_revision_conflict` интерфейс загружает актуальные данные и просит оператора повторно проверить цену перед сохранением.

## Предел журнала

При `pricing_revision_limit_reached` показывается предел редакций и подтверждение, что новая запись не создана.

## Валюта

При `unsupported_currency` выводится понятное сообщение, что поддерживается только `KGS`.

## Неопределённый успешный ответ

Если сервер вернул HTTP 200, но набор признаков результата не соответствует известному контракту, интерфейс не сообщает об успешном сохранении. Вместо этого выводится предупреждение и выполняется обновление данных.
