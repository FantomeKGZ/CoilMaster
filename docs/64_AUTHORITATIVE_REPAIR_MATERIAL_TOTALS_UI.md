# Серверные итоги материалов в интерфейсе списания

Мобильная и настольная страницы списания ремонта теперь используют серверное поле `material_totals` как основной источник разбивки расхода по материалам.

Запрос:

`GET /api/warehouse/write-offs?repair_id=<ID>`

## Условия доверия серверным итогам

Интерфейс использует `material_totals`, только если одновременно выполнены условия:

- `material_totals_source` равно `SERVER`;
- присутствует объект `material_totals`;
- `material_totals_match_total` равно `true`;
- `material_count_match_count` равно `true`.

При выполнении этих условий интерфейс показывает подпись:

`Источник итогов: сервер ESP32`

## Резервный расчёт

Если серверные итоги отсутствуют или одна из проверок согласованности не пройдена, интерфейс:

- рассчитывает разбивку из массива `items`;
- явно показывает предупреждение;
- не скрывает факт использования резервного клиентского расчёта.

Резервный расчёт группирует операции так:

- `wire_type=CU` — медь;
- `wire_type=AL` — алюминий;
- отсутствующий или иной материал — `UNKNOWN`.

## Обновление после списания

После успешного подтверждения списания повторно загружаются:

- список бухт;
- общий расход ремонта;
- серверная разбивка по материалам;
- проверки согласованности;
- история подтверждённых движений.
