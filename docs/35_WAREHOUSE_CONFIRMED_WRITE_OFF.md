# Подтверждённое списание провода по бухте

## Маршрут

`POST /api/warehouse/write-offs`

## Обязательные поля

- `spool_id` — выбранная бухта;
- `repair_id` — ремонт, к которому относится расход;
- `weight_before_g` — фактический вес бухты до работы;
- `weight_after_g` — фактический вес бухты после работы;
- `timestamp` — дата и время операции в ISO-формате.

Необязательное поле:

- `comment` — примечание мастера.

## Правила

- вес после должен быть меньше веса до;
- вес до должен совпадать с текущим весом бухты на microSD;
- нулевой расход запрещён;
- без настроенной общей цены операция не подтверждается;
- расход считается только как фактическая разница веса;
- в месячную и общую статистику попадают только записи со статусом `CONFIRMED`;
- цена и валюта копируются в движение в момент подтверждения;
- последующее изменение общей цены не меняет старую себестоимость;
- списание обязательно связано с ремонтом через `repair_id`.

## Безопасная последовательность записи

1. В `movements.ndjson` добавляется запись `PENDING`.
2. Проверяется выбранная активная бухта и точное совпадение веса до.
3. Файл бухт атомарно заменяется версией с новым весом.
4. В журнал движений добавляется полная запись `CONFIRMED`.
5. Если финальная запись не удалась, вес бухты возвращается к прежнему значению.

Статистика игнорирует `PENDING`, поэтому незавершённая операция не считается расходом.

## Пример успешного ответа

```json
{
  "confirmed": true,
  "movement_id": 17,
  "spool_id": 3,
  "repair_id": 42,
  "diameter_hundredths_mm": 80,
  "consumed_g": 845,
  "current_weight_g": 12575,
  "price_per_kg_minor": 125000,
  "currency": "KGS"
}
```
