# CoilMaster — Arduino Core

## Назначение

Arduino Uno является реальным контроллером станка. Она должна сохранять безопасное локальное управление намоткой даже при отсутствии ESP32.

## Ответственность

- опрос клавиатуры 4×4;
- внешняя физическая кнопка START на D10;
- LCD1602 I²C;
- датчик Холла SS49E на A0;
- SSR-40DA на D12;
- активный зуммер на D11;
- машина состояний намотки;
- прием заданий ESP32 по UART/CMP1;
- физический START и локальная пауза/продолжение;
- формирование фактических `RUN_STARTED` / `RUN_COMPLETED`;
- безопасная обработка `JOB_CANCEL`;
- аварийная синхронизация зависшего no-run задания.

## Ключевой safety boundary

Arduino является единственной стороной, которая управляет физическим процессом намотки и SSR. ESP32/Web не должны включать SSR и не могут инициировать physical START.

После reboot никакого automatic resume нет. SSR при запуске, сбросе и ошибке должен оставаться в безопасном состоянии `LOW`.

## Управление

| Ввод | Действие |
|---|---|
| A | старт или продолжение там, где это разрешено машиной состояний |
| B | локальная отмена/возврат согласно текущему состоянию |
| C | ручной режим согласно реализации |
| D | пауза |
| * | удалить последнюю цифру при вводе |
| # | подтвердить ввод |
| D10 | физический дубль START |

### Аварийная очистка зависшего задания ESP32

Специальная последовательность:

```text
D → * → # → D
```

с тайм-аутом между нажатиями используется только как recovery-механизм для рассинхронизации ESP32 ↔ Arduino.

Она **не означает завершение работы** и не должна генерировать `RUN_COMPLETED`.

Правила:

- если на Arduino есть remote job от ESP32, очистка разрешена только до physical START и только при отсутствии run evidence;
- если remote job уже отсутствует, Arduino подтверждает состояние `ALL_CLEAR`, не затрагивая локальную работу;
- при активной/приостановленной намотке и состояниях завершения последовательность не должна очищать задание;
- действие никогда не включает SSR и не списывает провод.

При успешной безопасной очистке Arduino отправляет CRC-защищенное подтверждение:

```text
CMP1|JOB_CANCEL_ACK|0|CANCELLED|ALL_CLEAR|C|<CRC>
```

ESP32 коррелирует `job_id=0` с текущим или восстановленным persisted job и закрывает его через обычный audited cancel path.

## Модель remote job

Arduino хранит только текущее необходимое задание, а не базу двигателей. Remote job содержит как минимум идентификаторы задания/сессии, тип обмотки, количество катушек и программу витков.

Повторная передача того же задания не должна создавать независимый дубликат.

## UART/CMP1 ответы

Для задания ESP32 Arduino использует:

- `JOB_ACK ... ACCEPTED` — задание принято и ожидает физический запуск;
- `JOB_ACK ... REJECTED` — задание отклонено;
- `JOB_CANCEL_ACK ... CANCELLED` — no-run задание очищено;
- `JOB_CANCEL_ACK ... REJECTED` — отмена небезопасна или относится не к активному remote job;
- `JOB_CANCEL_ACK|0|CANCELLED|ALL_CLEAR` — физически подтвержденное отсутствие активного remote job.

Повторный `JOB_CANCEL` должен быть идемпотентным: если remote job уже отсутствует, Arduino отвечает успешным clear-состоянием вместо создания вечного reject/retry цикла.

## Фактические события

Arduino является источником факта выполнения и передает ESP32 события намотки, включая `RUN_STARTED` и `RUN_COMPLETED` с корректными session/run identifiers.

`RUN_COMPLETED` сам по себе не списывает провод. Списание остается отдельной ручной операцией на ESP32 и должно быть связано с exact `spool_id`, `source_session_id`, `source_run_id`.

## Ограничения Arduino Uno

- избегать динамического выделения памяти;
- не использовать блокирующие длительные ожидания;
- использовать фиксированные буферы и ограниченные размеры кадров;
- строки интерфейса по возможности хранить во Flash;
- любые ошибки протокола/состояния должны fail-safe оставлять SSR выключенным.
