# CoilMaster — задания намотки и синхронизация с ESP32

Статус: базовая модель утверждена для дальнейшей реализации поверх CMP Protocol.

## 1. Основной принцип

Один запуск задания относится только к одному типу обмотки:

- `WORKING` — рабочая;
- `STARTING` — пусковая.

Количество катушек и число витков в них переменные.

Примеры программ:

```text
WORKING: 50 / 50 / 50 / 50
STARTING: 25 / 20 / 15
```

Для двигателя на 36 пазов одна обмоточная группа может включать две катушки по 35 витков:

```text
35 / 35
```

Arduino исполняет линейную очередь катушек. Полная структура двигателя, рабочая и пусковая программы и история хранятся на ESP32/microSD.

## 2. Текущее задание Arduino

На Arduino Uno хранится только текущее задание ограниченного размера:

```text
Job ID
Winding type
Coil count
Turns for each coil
Current coil index
Current actual turns
Source: LOCAL or WEB
Status
```

Для первой версии максимальное число катушек остается равным 10, как в старой прошивке. Изменение лимита допускается после измерения использования SRAM Arduino Uno.

## 3. Создание задания с Arduino

1. Пользователь вводит число катушек.
2. Вводит количество витков для каждой катушки.
3. Выбирается тип обмотки: рабочая или пусковая.
4. Arduino формирует задание и отправляет ESP32.
5. ESP32 присваивает/подтверждает `Job ID` и сохраняет запись на microSD.
6. ESP32 отвечает подтверждением сохранения.
7. Arduino показывает состояние готовности.
8. Оператор запускает намотку локально.

При отсутствии ESP32 Arduino не блокирует работу, но помечает задание как несинхронизированное.

## 4. Создание задания из Web-интерфейса

1. Пользователь выбирает двигатель или создает программу в Web-интерфейсе.
2. Выбирает только один тип обмотки: `WORKING` или `STARTING`.
3. ESP32 сохраняет задание и отправляет его Arduino.
4. Arduino проверяет длину, количество катушек, диапазоны витков и свое текущее состояние.
5. Arduino отвечает `JOB_ACCEPTED` или `JOB_REJECTED`.
6. Принятое задание отображается на LCD1602.
7. SSR не включается удаленно автоматически.
8. Фактический запуск выполняется клавишей `A` или внешней кнопкой D10.

## 5. Подтверждение фактической намотки

ESP32 не должна считать задание выполненным только потому, что оно было передано Arduino.

После каждой катушки Arduino отправляет отчет:

```text
Job ID
Coil index
Requested turns
Actual turns
Result
```

После последней катушки Arduino отправляет итоговый отчет задания.

Пример статусов:

```text
CREATED
SAVED
SENT
ACCEPTED
READY
RUNNING
PAUSED
COIL_COMPLETED
COMPLETED
CANCELLED
FAILED
RESULT_UNKNOWN
```

Только сообщение `COMPLETED`, полученное от Arduino, подтверждает фактическое завершение всей выбранной обмотки.

## 6. Отмена клавишей B

Клавиша `B`:

- выключает SSR;
- отменяет текущий локальный сеанс;
- очищает временный ввод;
- возвращает Arduino в главное меню;
- не удаляет сохраненные профили ESP32;
- отправляет `JOB_CANCELLED`, если задание уже имело `Job ID`.

## 7. Ответственность контроллеров

### Arduino Uno

Источник истины о физическом процессе:

- фактический старт;
- пауза и продолжение;
- текущая катушка;
- фактические витки;
- остановка SSR;
- завершение или отмена.

### ESP32

Источник истины о данных длительного хранения:

- профили двигателей;
- рабочие и пусковые программы;
- Job ID;
- история;
- Web-интерфейс;
- журнал подтверждений;
- несинхронизированные или неопределенные результаты.

## 8. Связь поверх CMP

CMP остается транспортным протоколом. Прикладной слой CoilMaster должен определить команды для:

- передачи задания;
- принятия или отклонения;
- подтверждения сохранения;
- изменения статуса;
- завершения катушки;
- завершения задания;
- отмены;
- запроса актуального состояния;
- повторной синхронизации после восстановления связи.

Точные числовые значения команд фиксируются отдельно в модуле прикладных команд после завершения модели Core.
