# CoilMaster — архитектура ESP32 и WEB-интерфейса

## 1. Назначение ESP32

ESP32 выполняет информационные, сетевые и сервисные функции проекта CoilMaster.

ESP32 не управляет критической логикой намоточного станка напрямую. Управление SSR, подсчет витков, обработка клавиатуры, кнопки START, зуммера и LCD1602 выполняются Arduino Uno.

ESP32 отвечает за:

- локальный Wi-Fi WEB-сервер;
- прием данных от Arduino Uno по UART через CMP Protocol;
- отображение текущего состояния намотки в браузере;
- хранение технологических и клиентских данных;
- журналирование выполненных работ;
- работу с microSD;
- резервное копирование;
- удаленную передачу заданий Arduino Uno;
- сервисные функции калибровки и диагностики;
- работу с RTC DS3231.

## 2. Доступ к WEB-интерфейсу

WEB-сервер запускается непосредственно на ESP32 и работает в локальной сети Wi-Fi.

Интерфейс должен корректно работать на:

- персональном компьютере;
- ноутбуке;
- смартфоне;
- планшете.

Интерфейс должен быть адаптивным и не требовать установки отдельного приложения.

## 3. Поток данных

```text
Датчики и органы управления
          |
      Arduino Uno
          |
     CMP Protocol
          |
   UART через LLC
          |
        ESP32
          |
   WEB-интерфейс
          |
 ПК / телефон / планшет
```

Arduino Uno является источником истины о фактическом процессе намотки.

ESP32 отображает данные, сохраняет задания и результаты, но не считает работу завершенной без подтверждения от Arduino Uno.

## 4. Основные страницы WEB-интерфейса

### 4.1 Главная страница

Показывает:

- состояние Arduino Uno;
- состояние связи UART;
- режим станка;
- выбранный тип обмотки;
- текущую катушку;
- общее количество катушек;
- текущие витки;
- заданные витки;
- состояние SSR;
- паузу;
- ручной режим;
- результат последнего задания;
- текущее время RTC.

### 4.2 Управление заданием

Позволяет:

- выбрать рабочую или пусковую обмотку;
- задать количество катушек;
- задать отдельное количество витков для каждой катушки;
- передать задание Arduino Uno;
- получить подтверждение принятия;
- отменить еще не начатое задание;
- видеть прогресс выполнения.

Удаленная передача задания не должна автоматически включать SSR. Фактический запуск выполняется клавишей `A` или внешней кнопкой START на Arduino Uno.

### 4.3 База клиентов

Функции:

- создание карточки клиента;
- редактирование карточки;
- просмотр истории работ клиента;
- поиск по имени, телефону, идентификатору или примечанию;
- архивирование записи без физического удаления истории.

### 4.4 База двигателей

Функции:

- создание технологической карточки двигателя;
- хранение количества пазов;
- хранение рабочей обмотки;
- хранение пусковой обмотки;
- хранение переменного количества катушек;
- хранение количества витков каждой катушки;
- хранение примечаний, схемы укладки и связанных параметров;
- поиск по модели, мощности, количеству пазов, клиенту и внутреннему идентификатору.

### 4.5 Журнал намоток

Для каждой работы сохраняются:

- уникальный Job ID;
- дата и время начала;
- дата и время завершения;
- клиент;
- двигатель;
- тип обмотки;
- источник задания: Arduino или WEB;
- список заданных витков;
- список фактически подтвержденных витков;
- результат каждой катушки;
- итоговый статус;
- причина отмены или ошибки;
- статус синхронизации с Arduino.

## 5. Статусы задания

Рекомендуемые статусы:

```text
CREATED
SAVED
SENT_TO_ARDUINO
ACCEPTED
READY
RUNNING
PAUSED
COIL_COMPLETED
COMPLETED
CANCELLED
FAILED
RESULT_UNKNOWN
```

Статус `COMPLETED` устанавливается ESP32 только после получения итогового подтверждения от Arduino Uno.

## 6. Хранение данных

### 6.1 microSD

microSD является основным съемным хранилищем для:

- базы клиентов;
- базы двигателей;
- журнала намоток;
- резервных копий;
- экспортов;
- диагностических журналов.

### 6.2 Формат данных

На первом этапе рекомендуется использовать компактные текстовые или двоичные записи с контролем версии структуры.

Для WEB-обмена допускается JSON, но постоянное хранение должно учитывать ограничения RAM ESP32 и устойчивость к внезапному отключению питания.

### 6.3 Защита данных

Требования:

- запись через временный файл и атомарную замену, где возможно;
- контроль версии схемы данных;
- проверка целостности записей;
- резервная копия перед миграцией формата;
- отсутствие перезаписи подтвержденной истории без явного действия пользователя.

## 7. Резервное копирование

WEB-интерфейс должен поддерживать:

- создание полного бэкапа;
- скачивание бэкапа на ПК или телефон;
- хранение нескольких резервных копий на microSD;
- восстановление после подтверждения пользователя;
- проверку версии и целостности перед восстановлением.

В бэкап входят:

- клиенты;
- двигатели;
- журнал намоток;
- настройки;
- параметры калибровки;
- версия схемы базы данных.

## 8. Работа без ESP32

Arduino Uno должна сохранять возможность автономной намотки при отсутствии ESP32.

При восстановлении связи Arduino передает ESP32:

- текущее состояние;
- активное задание;
- последнюю завершенную катушку;
- итог незарегистрированной работы, если такой отчет сохранен локально.

## 9. Безопасность управления

- WEB-команда не должна напрямую обходить машину состояний Arduino.
- ESP32 не должна считать SSR включенным только по отправленной команде; состояние подтверждает Arduino.
- Удаленный запуск без физического подтверждения возле станка запрещен в базовой версии.
- Команды должны содержать Job ID и проверяться на повторную передачу.
- Повторно полученная команда не должна создавать дубликат задания.

## 10. Разделение ответственности

### Arduino Uno

- реальное управление станком;
- подсчет витков;
- SSR;
- LCD1602;
- клавиатура;
- внешняя кнопка START;
- ручной режим;
- пауза;
- подтверждение завершения катушки и задания.

### ESP32

- Wi-Fi;
- WEB-интерфейс;
- базы данных;
- microSD;
- RTC;
- журналирование;
- резервное копирование;
- подготовка и передача заданий;
- сервисные экраны;
- удаленная диагностика.
