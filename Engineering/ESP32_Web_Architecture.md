# CoilMaster — архитектура ESP32 и WEB-интерфейса

## 1. Назначение ESP32

ESP32 выполняет информационные, сетевые и сервисные функции проекта CoilMaster.

ESP32 не управляет критической логикой намоточного станка напрямую. Управление SSR, подсчет витков, обработка клавиатуры, кнопки START, зуммера и LCD1602 выполняются Arduino Uno.

ESP32 отвечает за:

- локальный Wi-Fi WEB-сервер;
- прием данных от Arduino Uno по UART через CMP Protocol;
- отображение текущего состояния намотки в браузере;
- хранение технологических и клиентских данных;
- журналирование выполненных работ;
- работу с microSD;
- резервное копирование;
- удаленную передачу заданий Arduino Uno;
- сервисные функции калибровки и диагностики;
- работу с RTC DS3231;
- размещение нескольких независимых WEB-сайтов на microSD;
- выбор пользователем версии интерфейса для ПК или мобильного устройства.

## 2. Доступ к WEB-интерфейсу

WEB-сервер запускается непосредственно на ESP32 и работает в локальной сети Wi-Fi.

Интерфейс должен корректно работать на:

- персональном компьютере;
- ноутбуке;
- смартфоне;
- планшете.

При первом входе пользователь попадает на стартовый портал ESP32. Портал показывает список доступных сайтов и позволяет вручную выбрать:

- сайт CoilMaster;
- сайт базы данных;
- сервисный сайт;
- другие сайты, размещенные на microSD;
- версию сайта для ПК;
- версию сайта для мобильного телефона или планшета.

Автоматическое определение типа устройства может использоваться только как рекомендация. Окончательный выбор всегда остается за пользователем.

## 3. Многосайтовая структура

WEB-сервер ESP32 должен поддерживать несколько независимых сайтов, размещенных в отдельных каталогах microSD.

Рекомендуемая структура:

```text
/web/
├── portal/
│   ├── index.html
│   ├── app.js
│   └── style.css
│
├── coilmaster/
│   ├── desktop/
│   │   ├── index.html
│   │   ├── app.js
│   │   ├── style.css
│   │   └── assets/
│   └── mobile/
│       ├── index.html
│       ├── app.js
│       ├── style.css
│       └── assets/
│
├── database/
│   ├── desktop/
│   │   ├── index.html
│   │   ├── app.js
│   │   ├── style.css
│   │   └── assets/
│   └── mobile/
│       ├── index.html
│       ├── app.js
│       ├── style.css
│       └── assets/
│
├── service/
│   ├── desktop/
│   └── mobile/
│
└── sites.json
```

Файл `sites.json` является реестром сайтов. Он хранит:

- уникальный идентификатор сайта;
- отображаемое название;
- путь к версии для ПК;
- путь к мобильной версии;
- признак доступности;
- порядок отображения;
- минимальную роль пользователя, если позже появится авторизация.

Пример логической записи:

```json
{
  "id": "database",
  "title": "База данных",
  "desktop": "/web/database/desktop/index.html",
  "mobile": "/web/database/mobile/index.html",
  "enabled": true
}
```

## 4. Маршруты WEB-сервера

Рекомендуемые маршруты:

```text
/                         стартовый портал
/site/{id}/desktop        версия выбранного сайта для ПК
/site/{id}/mobile         мобильная версия выбранного сайта
/api/sites                список доступных сайтов
/api/system/status        состояние ESP32 и Arduino
/api/winding/*             управление заданиями намотки
/api/database/*            клиенты, двигатели и журнал
/api/service/*             калибровка и диагностика
```

HTML, CSS, JavaScript, изображения и прочие статические файлы читаются с microSD.

API остается общим для всех сайтов. Это исключает дублирование серверной логики и позволяет разным интерфейсам работать с одной базой данных и одним состоянием станка.

## 5. Выбор ПК или мобильной версии

При открытии сайта пользователь выбирает один из вариантов:

```text
Открыть версию для ПК
Открыть мобильную версию
```

Выбор может сохраняться в браузере через `localStorage` или cookie, но на стартовом портале должна оставаться возможность изменить его вручную.

Версии для ПК и телефона могут иметь разную компоновку, но обязаны использовать одинаковые API и одинаковые правила безопасности.

## 6. Поток данных

```text
Датчики и органы управления
          |
      Arduino Uno
          |
     CMP Protocol
          |
   UART через LLC
          |
        ESP32
          |
  Общее серверное API
          |
  +-------+---------+---------+
  |                 |         |
CoilMaster       Database   Service
  |                 |         |
ПК/мобильный     ПК/мобильный ПК/мобильный
```

Arduino Uno является источником истины о фактическом процессе намотки.

ESP32 отображает данные, сохраняет задания и результаты, но не считает работу завершенной без подтверждения от Arduino Uno.

## 7. Основные сайты и страницы

### 7.1 Стартовый портал

Показывает:

- доступные сайты;
- статус microSD;
- статус Arduino Uno;
- состояние UART;
- текущее время RTC;
- выбор версии для ПК или мобильного устройства.

### 7.2 Сайт CoilMaster

Показывает:

- состояние Arduino Uno;
- состояние связи UART;
- режим станка;
- выбранный тип обмотки;
- текущую катушку;
- общее количество катушек;
- текущие витки;
- заданные витки;
- состояние SSR;
- паузу;
- ручной режим;
- результат последнего задания;
- текущее время RTC.

Позволяет:

- выбрать рабочую или пусковую обмотку;
- задать количество катушек;
- задать отдельное количество витков для каждой катушки;
- передать задание Arduino Uno;
- получить подтверждение принятия;
- отменить еще не начатое задание;
- видеть прогресс выполнения.

Удаленная передача задания не должна автоматически включать SSR. Фактический запуск выполняется клавишей `A` или внешней кнопкой START на Arduino Uno.

### 7.3 Сайт базы данных

Сайт базы данных является отдельным интерфейсом, работающим с данными на microSD.

Разделы:

- база клиентов;
- база двигателей;
- журнал намоток;
- поиск;
- экспорт;
- резервное копирование;
- восстановление.

#### База клиентов

Функции:

- создание карточки клиента;
- редактирование карточки;
- просмотр истории работ клиента;
- поиск по имени, телефону, идентификатору или примечанию;
- архивирование записи без физического удаления истории.

#### База двигателей

Функции:

- создание технологической карточки двигателя;
- хранение количества пазов;
- хранение рабочей обмотки;
- хранение пусковой обмотки;
- хранение переменного количества катушек;
- хранение количества витков каждой катушки;
- хранение примечаний, схемы укладки и связанных параметров;
- поиск по модели, мощности, количеству пазов, клиенту и внутреннему идентификатору.

#### Журнал намоток

Для каждой работы сохраняются:

- уникальный Job ID;
- дата и время начала;
- дата и время завершения;
- клиент;
- двигатель;
- тип обмотки;
- источник задания: Arduino или WEB;
- список заданных витков;
- список фактически подтвержденных витков;
- результат каждой катушки;
- итоговый статус;
- причина отмены или ошибки;
- статус синхронизации с Arduino.

### 7.4 Сервисный сайт

Содержит:

- калибровку датчика Холла;
- диагностику клавиатуры;
- тест LCD1602;
- тест SS49E;
- безопасный тест SSR;
- тест зуммера;
- диагностику UART;
- диагностику RTC DS3231;
- состояние microSD;
- системный журнал.

## 8. Добавление других сайтов

Новый сайт должен добавляться без перепрошивки основной логики ESP32, если его серверные функции уже поддерживаются общим API.

Для добавления сайта достаточно:

1. создать отдельную папку в `/web/`;
2. добавить подпапки `desktop` и `mobile`;
3. загрузить статические файлы;
4. добавить запись в `sites.json`;
5. перезапустить WEB-сервис или перечитать реестр сайтов.

Сайт не получает прямого доступа к произвольным файлам microSD. Все операции с базой данных и системными настройками выполняются только через проверяемые API ESP32.

## 9. Статусы задания

Рекомендуемые статусы:

```text
CREATED
SAVED
SENT_TO_ARDUINO
ACCEPTED
READY
RUNNING
PAUSED
COIL_COMPLETED
COMPLETED
CANCELLED
FAILED
RESULT_UNKNOWN
```

Статус `COMPLETED` устанавливается ESP32 только после получения итогового подтверждения от Arduino Uno.

## 10. Хранение данных

### 10.1 microSD

microSD является основным съемным хранилищем для:

- WEB-сайтов;
- базы клиентов;
- базы двигателей;
- журнала намоток;
- резервных копий;
- экспортов;
- диагностических журналов.

WEB-файлы и данные должны храниться в разных корневых каталогах, например:

```text
/web/       статические сайты
/data/      рабочие базы
/backups/   резервные копии
/logs/      журналы
/config/    настройки и реестр сайтов
```

### 10.2 Формат данных

На первом этапе рекомендуется использовать компактные текстовые или двоичные записи с контролем версии структуры.

Для WEB-обмена допускается JSON, но постоянное хранение должно учитывать ограничения RAM ESP32 и устойчивость к внезапному отключению питания.

### 10.3 Защита данных

Требования:

- нормализация и проверка путей файлов;
- запрет выхода за разрешенные каталоги;
- отсутствие прямой выдачи служебных файлов базы;
- запись через временный файл и атомарную замену, где возможно;
- контроль версии схемы данных;
- проверка целостности записей;
- резервная копия перед миграцией формата;
- отсутствие перезаписи подтвержденной истории без явного действия пользователя.

## 11. Резервное копирование

WEB-интерфейс должен поддерживать:

- создание полного бэкапа;
- скачивание бэкапа на ПК или телефон;
- хранение нескольких резервных копий на microSD;
- восстановление после подтверждения пользователя;
- проверку версии и целостности перед восстановлением.

В бэкап входят:

- клиенты;
- двигатели;
- журнал намоток;
- настройки;
- параметры калибровки;
- версия схемы базы данных;
- реестр сайтов `sites.json`.

Статические WEB-сайты могут резервироваться отдельным архивом.

## 12. Работа без ESP32

Arduino Uno должна сохранять возможность автономной намотки при отсутствии ESP32.

При восстановлении связи Arduino передает ESP32:

- текущее состояние;
- активное задание;
- последнюю завершенную катушку;
- итог незарегистрированной работы, если такой отчет сохранен локально.

## 13. Безопасность управления

- WEB-команда не должна напрямую обходить машину состояний Arduino.
- ESP32 не должна считать SSR включенным только по отправленной команде; состояние подтверждает Arduino.
- Удаленный запуск без физического подтверждения возле станка запрещен в базовой версии.
- Команды должны содержать Job ID и проверяться на повторную передачу.
- Повторно полученная команда не должна создавать дубликат задания.
- Произвольные сайты не должны иметь прямого доступа к GPIO, SSR или UART.
- Управляющие операции выполняются только через ограниченный серверный API.

## 14. Разделение ответственности

### Arduino Uno

- реальное управление станком;
- подсчет витков;
- SSR;
- LCD1602;
- клавиатура;
- внешняя кнопка START;
- ручной режим;
- пауза;
- подтверждение завершения катушки и задания.

### ESP32

- Wi-Fi;
- многосайтовый WEB-сервер;
- стартовый портал;
- выдача ПК и мобильных версий сайтов;
- общие API;
- базы данных;
- microSD;
- RTC;
- журналирование;
- резервное копирование;
- подготовка и передача заданий;
- сервисные экраны;
- удаленная диагностика.
