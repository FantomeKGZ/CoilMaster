# CoilMaster — Web API ESP32

## Назначение

API является единственной разрешенной точкой доступа сайтов к данным и функциям ESP32. Web-файлы не обращаются напрямую к GPIO, UART или файловой системе.

## Базовые группы

```text
/api/system/*
/api/jobs/*
/api/clients/*
/api/motors/*
/api/repairs/*
/api/windings/*
/api/history/*
/api/service/*
/api/backups/*
/api/sites/*
```

## Система

- `GET /api/system/status` — ESP32, Arduino, UART, SD, RTC, память;
- `GET /api/system/live` — текущее состояние намотки;
- `GET /api/system/time` — время RTC.

## Задания

- `POST /api/jobs` — создать задание;
- `POST /api/jobs/{id}/send` — отправить Arduino;
- `GET /api/jobs/{id}` — статус и фактические результаты;
- `POST /api/jobs/{id}/cancel` — отменить незапущенное задание.

Удаленный вызов не должен запускать SSR. Запуск подтверждается возле станка.

## Клиенты и двигатели

Поддерживаются создание, чтение, изменение, архивирование и поиск. Физическое удаление связанной истории по умолчанию запрещено.

## История и объединение

API должен:

- возвращать отдельные фактические запуски;
- группировать одинаковые программы по выбранному периоду;
- позволять связать несколько запусков с одним ремонтом;
- показывать, например, `50/50/50 × 2 сегодня`;
- сохранять исходные записи после объединения.

## Сервис

- чтение Hall A0;
- изменение порога с проверкой диапазона;
- диагностика LCD, клавиатуры, зуммера, RTC и UART;
- SSR-тест только через двухэтапное подтверждение и при безопасном состоянии Arduino.

## Формат ответа

```json
{
  "ok": true,
  "data": {},
  "error": null,
  "requestId": "..."
}
```

Ошибки содержат стабильный код, понятное сообщение и не раскрывают внутренние пути файловой системы.

## Версионирование

Первая версия публикуется под `/api/v1/`. Несовместимые изменения требуют новой версии API.
