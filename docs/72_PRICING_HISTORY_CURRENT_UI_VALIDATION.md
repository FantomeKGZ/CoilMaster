# Проверка истории цены против активной калькуляции в интерфейсе

Мобильная и настольная страницы калькуляции теперь используют серверные инварианты из:

`GET /api/repairs/pricing-history?repair_id=<ID>`

История считается подтверждающей текущую активную цену только когда одновременно выполнены условия:

- `source = APPEND_ONLY_LOG`;
- `current_pricing_source = LATEST_APPEND_ONLY_REVISION`;
- `count` совпадает с количеством элементов `items`;
- `latest_revision` совпадает с номером последней записи;
- `history_count_matches_current = true`;
- `history_latest_values_match_current = true`;
- `history_latest_timestamp_matches_current = true`;
- `history_matches_current_pricing = true`.

## Поведение интерфейса

При успешной проверке последняя редакция помечается как `текущая`, а блок активной цены сообщает, что она подтверждена последней редакцией журнала ESP32.

При расхождении:

- последняя запись помечается только как `последняя в журнале`;
- интерфейс показывает отдельное предупреждение;
- активная цена и журнал остаются видимыми для диагностики;
- интерфейс не заявляет, что последняя запись является текущей.

Показываются значения активной цены, возвращённые сервером:

- стоимость работы;
- цена клиенту;
- валюта;
- дата и время обновления.
