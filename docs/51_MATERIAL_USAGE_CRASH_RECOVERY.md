# Аварийно-безопасное списание материалов

## Проблема

Раньше подтверждение расхода материала выполнялось в два независимых шага:

1. уменьшение остатка материала;
2. добавление записи расхода в `usage.ndjson`.

При отключении питания между этими шагами остаток мог уменьшиться без появления записи расхода.

## Новая схема

Перед изменением остатка ESP32 создаёт файл подготовленной транзакции:

`/data/materials/usage.pending`

В нём сохраняются:

- `usage_id`;
- `material_id`;
- остаток до списания;
- остаток после списания;
- готовая строка для `usage.ndjson`.

Порядок выполнения:

1. подготовить и записать `usage.pending`;
2. уменьшить остаток в `materials.ndjson`;
3. добавить запись в `usage.ndjson`;
4. удалить `usage.pending`.

## Восстановление после перезапуска

Во время `MaterialLedger::begin()` система проверяет наличие `usage.pending`.

- Если `usage_id` уже есть в журнале расхода, удаляется только устаревший pending-файл.
- Если остаток ещё равен значению до списания, транзакция считается не начатой и pending-файл удаляется.
- Если остаток равен значению после списания, недостающая запись расхода дописывается в журнал.
- Если остаток не совпадает ни с одним ожидаемым значением, модуль не переходит в состояние `ready`, чтобы не скрыть повреждение данных.

## Результат

После сбоя система не должна оставлять подтверждённое уменьшение остатка без соответствующей записи расхода.

Одновременно допускается только одна подготовленная операция списания материалов.
